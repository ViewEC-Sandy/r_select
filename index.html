上傳銷售 / 商品 CSV・Excel

指定欄位更新

CSV / Excel 至少需要【商品規格管理編號】作為更新鍵；【商品管理編號】可選填，若提供則會額外檢查一致性。只有檔案中實際存在且該列有填值的欄位才更新；未提供的欄位與空白儲存格都保留 Firebase 原資料，不會被清空。

可更新：商品標題、規格1～3、備註、台灣樂天URL、日安URL、日本URL、RTWBase SKU、日幣售價、樂天台幣售價、日安台幣售價、重量、上架狀態、頁面檢視、銷售商品數、銷售訂單數。若只校正日幣售價，只需提供【商品規格管理編號】＋【日幣售價(JPY)】兩欄。更新後商品成本會依新日幣售價重新計算，但既有台幣售價與其他商品資料會保留。

台灣樂天｜全店訪問報告（獨立匯入）

用途：全店流量（PV + UV）。系統先讀取【時間範圍】，再讀取【所有頁面檢視】與【所有非重複訪客】，並保存【全店頁面】【商品頁面】【店家類別頁面】【店家首頁】各自的 PV / UV。支援兩種【時間範圍】格式：① 2026/01/01 ~ 2026/07/31；② 2026/07 ~ 2026/07。若只有年月，系統會自動換算為該月第一天到最後一天，例如 2026/07 ~ 2026/07 → 2026-07-01 ~ 2026-07-31。單一報告仍只形成 1 個期間資料點；可一次選取多份不同期間報告形成流量趨勢。

台灣樂天｜商品銷售數據（獨立匯入）

等待匯入0%

依樂天實際表頭讀取：【商品管理編號 (Base SKU)】、【銷售】、【售出單位】、【訂單計數】、【頁面檢視】、【非重複訪客】、【轉換率】。系統會自動偵測真正的表頭列，不限定一定在 Excel 第 1 列；匯入前會直接顯示偵測到的【頁面檢視】欄、有效筆數與總和，避免資料被寫成 0。轉換率優先使用報表原值，空白時才使用「訂單計數 ÷ 頁面檢視」。

台灣樂天｜訂單銷售報表讀取方式

訂單號碼、訂單日期、顧客已付金額、運費、下載時的訂單狀態。此區負責唯一訂單、總營業額與已收運費；【銷售】【售出單位】【訂單計數】改由上方「商品銷售數據」獨立匯入。

以【訂單號碼】作為唯一訂單識別值：同一訂單即使在報表中有多個商品列，訂單數、顧客已付金額與運費都只計算一次；重複上傳同一訂單時會更新既有訂單，不會新增第二筆，因此不會重複計入營業額、已收運費或訂單數。「下載時的訂單狀態」為「已取消」的資料不列入任何統計。

日安優物 Shopline｜銷售報表讀取方式

訂單號碼 → 唯一訂單值；訂單日期 → 銷售日期；付款總金額 → 訂單營業額；運費 → 已收運費。

商品貨號 → 商品管理編號；商品結帳價格 → 商品層級營業額分配依據；數量 → 銷售商品數。

總營業額以訂單號碼去重後加總付款總金額，避免多商品訂單重複計算。

商品主檔讀取方式

商品規格管理編號、商品管理編號、商品標題、商品網址、RTWBase SKU、參考URL #1、價格等欄位。來源欄位【價格】改視為【日幣售價(JPY)】直接寫入；系統依【商品成本匯率】換算商品成本(TWD)，再分別依樂天與日安優物各自的平台費率、目標利潤率、免運門檻、日本國內運費、物流成本與客收運費規則，計算兩個平台的台幣售價、平台費、利潤、利潤率與目標利潤建議售價。不再由台幣售價反推日幣價格。所有數值欄位在匯入時都會先自動轉成真正的 Number 再寫入 Firestore，即使來源 Excel 顯示「數字以文字儲存」也可讀取；支援例如 1,000、NT$1,000、￥5,000、全形數字等格式。商品編號、訂單號碼、SKU 等識別碼仍保留文字格式，避免前導 0 被吃掉。

快速建立模式只寫入商品識別、標題/規格、日幣價格、重量與網址等主檔必要資料；台幣售價與利潤由系統依兩平台 Params 自動計算；完整更新模式保留既有合併邏輯。匯入前會先做 1 筆 Firestore 寫入/刪除連線測試。
